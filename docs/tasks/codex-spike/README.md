# T1 Codex app-server qualification

This is a standalone Rust prototype, outside the application workspace. It does
not edit WordCraft documents. Run from this directory with `codex` on PATH (or
set `WORDCRAFT_CODEX_BINARY` to the executable). All runtime configuration and
synthetic conversations stay in ignored directories below this directory.

```
cargo test
cargo clippy --all-targets -- -D warnings
cargo run
cargo run -- --auth-check
```

The main probe runs real Codex app-server against a loopback Responses fixture
and a purpose-built stdio MCP fixture. It asserts the advertised tool classes,
observes two text deltas, completes and resumes a thread, approves an MCP
elicitation, interrupts a slow response, detects child exit, and reaps the child.
It uses stable protocol capabilities and no dynamic tools. The MCP resource
helpers are built-in dispatchers; the only configured server is the fixture,
which denies every unlisted request. No general filesystem or shell tool is
advertised. T3 must separately verify the real document profile.

The auth probe starts with an isolated, ephemeral credential store. It checks
signed-out status, starts the supported managed browser login (without opening
the browser or logging its URL), cancels it, and signs out of that isolated
profile. It does not sign the user's normal Codex profile out.

## Compatibility matrix (2026-10-16)

| Capability | Codex 0.162.1, macOS arm64 | Evidence |
| --- | --- | --- |
| Stable stdio initialize/initialized | Pass | main and auth probes |
| Version match | Exactly 0.162.1 required | validator tests; earlier/later versions refused |
| Thread start/resume | Pass | real app-server with synthetic conversation |
| Turn start, incremental text, completion | Pass | two separate SSE deltas through app-server |
| Interrupt | Pass, acknowledgement | slow second response; no live model inference |
| Approved tool round trip | Pass | stable mcpServer/tool/call and MCP elicitation |
| Restricted tool classes | Pass for fixture configuration | shell/filesystem/image/browser/connector tools absent; only request_user_input and isolated MCP dispatchers/profile present |
| Signed-out status | Pass | account=null, requiresOpenaiAuth=true |
| Managed browser login and cancellation | Pass | login URL origin checked in memory; URL withheld |
| Isolated sign-out | Pass | account/logout on ephemeral test profile |
| Existing normal-profile authentication | ChatGPT account present | separate read-only initialize/account/read probe; no credentials read or copied |
| Missing binary | Pass | process spawn error test |
| Unsupported version | Pass | exact-version rejection tests |
| Malformed/partial/oversized streams | Pass | fake stream decoder tests with two-byte reader buffer |
| Child exit and cleanup | Tested by main probe | process kill/wait and rejected subsequent request |
| Hosted inference with isolated profile | Not tested | no sign-in performed for the new profile; required for final native end-to-end validation |
| Windows/Linux/BSD | Not tested here | platform qualification belongs to T9 |

0.162.1 is the minimum **tested** version, not a claim that earlier versions
cannot work. Ship a closed compatibility range of exactly that version until a
new version passes this suite. The stable schema generated by
`codex app-server generate-json-schema --out <directory>` is saved in
`schema/0.162.1.json`. Runtime behavior takes precedence: this runtime rejects
`approval_policy="untrusted"` despite its presence in the generated schema.
Use `on-request`; WordCraft must independently gate all document mutations.

Distribution recommendation: discover an installed runtime or let users select
its executable in the pane; show the exact supported version and actionable
setup/recovery. Never silently install or upgrade it. Use a dedicated runtime
home so unrelated MCP servers, plugins and global configuration are not inherited.
Use app-server-managed browser sign-in in that profile; WordCraft stores no
credentials. The user must authenticate the dedicated profile before hosted
inference. Persistent thread content belongs to the Codex runtime; WordCraft
settings contain references only. Do not log protocol payloads.

Official references inspected: [app-server](https://learn.chatgpt.com/docs/app-server)
and [configuration](https://learn.chatgpt.com/docs/config-file/config-reference).
These probe results are protocol evidence, not a completed product or release
verification. No T2–T11 work is implied.
